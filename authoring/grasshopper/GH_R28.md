# R28 — third definition: room configuration → cassette skeleton → detailing

Run **CREATE_LAYOUT_GRASSHOPPER.py** in Rhino 8 Python 3, with Grasshopper open and a millimetre document active. Extract the entire package into a fresh folder first. It creates and opens `OBTP_Room_Configurator_R28_<timestamp>.gh` beside its supporting modules. Native Rhino/GH acceptance remains outstanding; the ZIP supplies the creator and code, not a natively tested prebuilt binary definition.

The existing `CREATE_GRASSHOPPER.py` (R27 main) and `CREATE_RESEARCH_GRASSHOPPER.py` (system specimens) are unchanged. This is an additional independent canvas.

## A — programme and plan

0. Select **Sauna / Studio / Living studio**.
1. Each function Value List is one room. Duplicate a list and Shift-connect its output into **functions** on the room collector. Connect 1–6 lists. Repeated functions create distinct instances. Wire order assigns R01…R06; deleting or reordering connections changes these IDs, so check your pair rules afterward.
2. Set **may / must / cannot share an edge**. A Pair rule has Room A, Room B and relationship selectors. Duplicate the three selectors and Pair rule component to add another constraint, then Shift-connect it to the rules input. An unconnected rule input is valid. Disconnect the example pair rules when working with only one room.
3. Set **totally open / partition with opening / closed partition** through the second Pair rule group. A specified treatment requires the two rooms to be neighbours. Conflicting adjacency and boundary rules reject the layout. Unspecified pairs may meet; actual neighbours default to a partition with opening.
4. Control the **overall** envelope: X length 3–14 cells ×900 mm, Y width 2–3 cells ×1200 mm. Room lengths are allocated from function-specific study minima and weights, not individual size sliders. Infeasible programmes explain the minimum required length. Select one of at most eight valid orders; the report gives the actual valid arrangement range.

The result is a single-row plan and connection graph, independent of structural generation. Rectangular multi-row plans, imported Rhino plans, curves, branching layouts and arbitrary holes are not supported. Graph edges are labelled with boundary type. Totally open means no partition is generated, not a certified post-free span.

The main entrance prefers the Entrance function, otherwise the first room instance. Choose front/back/west/east. A short-side entrance constrains its room to an end. A closed partition divides the access graph; each disconnected group receives an exterior entry. Opening fit is checked before 3D generation. Door thresholds, clear passage, circulation, fire and accessibility compliance remain unresolved.

## B — cassette skeleton

Select Cassette (the only system), flat/drainage or single-slope roof, and timber-rail or concrete-grillage foundation study. The adapter derives exterior wall runs, partitions, opening hosts and floor/roof boundaries from the resolved plan. It calls shared cassette wall/slab member recipes; it never calls the preset building generator or programme-specific arrangement function.

The skeleton preview contains frame/support members, including the weather-roof framing: changing roof type changes this preview. Structural sheet parts are generated by the same recipes and reserved for the next stage; they remain present in the detailed model and schedule. Foundation supports use a 1800×1200 rhythm with explicit terminal intervals. Sections, span feasibility, diaphragm action, lintels, fastening and pile capacity are not engineered.

## C — detailing

- **Terrace:** None, entrance side, two opposite sides, L, or U. U is both long sides and one short end, always including the entrance edge. For a long-side entrance, Return selects west/east; for a short-side L entrance it selects front/back. Deck boards retain X direction across returns. Exposed terrace edges have cover boards; shared seams are not doubled. The combined foundation follows the resulting rectangular platform extent.
- **Sauna outdoor shower and bench:** compact reservations on available terrace space, kept clear of modelled door approaches and one another. The shower has a three-sided screen and schematic fixture; the bench has front/end boards. These are NOT yet the older integrated storage/shower/bench niche. They do not subdivide an indoor room, specify plumbing or establish wet-area usability. Inactive building types reject these options explicitly.
- **Studio summer passage:** located in A4 because it changes the plan before framing. Uses Hall, otherwise Entrance, as an interior room in the row, with at least one room on each side. Requires at least three rooms and reserves at least three X cells for the passage. Two opposite exterior openings have 1800×1900 mm schematic rough openings and two leaf representations each. Frame outside dimensions, actual leaf sizes, threshold and clear passage are unverified; no supplier selection is claimed.
- **Paneling:** structural panels; panels + cavity insulation; or panels + insulation + timber lining. Structural sheathing is never removed by these choices. Lining and insulation are geometric study layers. Air/vapour control, weather-cover attachment/ventilation, waterproofing and interior details require further design.
- **Façade:** finish Yes/No. Finish boards and their optional backing are added or omitted physically. Primary counts use the existing façade-board exclusion, with a separate cladding schedule. No part-diversity reduction is claimed by choosing an unfinished build-up.

No windows, equipment layouts or service routes are automatically specified. The living option is a functional planning category, not a verified habitable building. The study area bound does not establish SLD/permit exemption.

## D — display and export

Retains connected-wall assembly progress, stable part colours and Structure + panels / Building without façade / Complete preview. Turn off the final native Custom Preview while inspecting the separate skeleton preview if both obscure each other. Plan/graph preview is offset away from the model.

Export writes the complete scene, portable/native 3DM, model-linked SVG plan/axon, parts CSV and primary/cladding schedules JSON into `exports-room-config/<geometry hash>`. It never exports the filtered preview. PDF is not introduced in this third workflow. Existing two definitions and their document recipes remain unchanged.

All three A/B/C outputs are inspectable; stage input hashes prevent stale edited payloads. Invalid input clears downstream results and reports the responsible stage. Read the first error; later errors usually mean its output is unavailable.
